# TASK SCOPE — ISSUE #278

## 1. Requirements Breakdown

- **Target Objective:** Fix broken CSS rendering of the offering "Story" content when viewed live in the app (Pages tab > offering, e.g. Migration Accelerator > The Story). Reported symptoms: missing padding/margins throughout (problem-statement bullets, capability cards, client-profile stats, FAQ rows), overlapping icon+label badges on the capability cards' two-letter icon chips (In/Au/De/Pl/Sp/Ex) and on the FAQ "YES +" / "QUALIFIED YES +" pills, and inconsistent spacing between the numbered route steps (Ingest/Audit/Decide/Plan/Execute) and their labels / section dividers.

- **System Component Impacted:** LWC — `force-app/main/default/lwc/gtmStory/` (`gtmStory.css` / `gtmStory.html` / `gtmStory.js`). This is the single renderer used both for the live in-app Story page and for the GTM Content Manager's live preview (`force-app/main/default/lwc/gtmPagePreview/gtmPagePreview.html` embeds the identical `<c-gtm-story>` component). There is no separate "design tool" renderer in this codebase — the issue's hypothesis that the CSS "was only ever verified in an isolated design-tool preview" does not match what the code actually does; both surfaces share one component and one stylesheet, so this is not an app-context-vs-preview split.

### Root cause found (verified against git history, not guessed)

`gtmStory.css` currently opens with a comment block claiming the page's shared design tokens "used to live in its own CSS-only module (`c/gtmBrandTokens`, imported here with `@import 'c/gtmBrandTokens';`)... so it was folded directly in here instead (issue #33)."

That claim is only half true. Tracing the actual diff at commit `4fe6b5c8` ("fix(ci): zero out check-references.py debt and make agent-ci-gate baseline-aware (issue #33)"):

- It deletes `force-app/main/default/lwc/gtmBrandTokens/gtmBrandTokens.css` (390 lines) and the rest of that LWC bundle outright, replacing the single line `@import 'c/gtmBrandTokens';` at the top of `gtmStory.css` with ~180 lines of `:host { --ps-*: ...; }` **token** declarations (colors, type scale, shape, motion, elevation).
- It does **not** port over the layout **primitives** that also lived in the deleted `gtmBrandTokens.css`: `.boxed` (page gutter container), `.ps-grid` (the 12-column responsive grid), `.pc-full` / `.pc-rail` / `.pc-railbody` / `.pc-text` / `.pc-media` / `.pc-narrative` (column-placement classes used by every section layout), `.ps-band` / `.ps-band--tint` / `.ps-band--invert` / `.ps-band--asym` (section background + block padding/"rhythm"), the `--ps-gutter` / `--ps-rhythm` / `--ps-s-16` / `--ps-s-32` / `--ps-s-40` spacing scale, `.ps-eyebrow` / `.ps-display` (typography primitives), the `.rv` / `.rv-l` / `.rv-r` / `.rv-stagger` scroll-reveal rules, `.ps-spacer` (the inter-section rhythm spacer), and `.ps-scope`.
- Confirmed by direct grep of the current file: those class **names are referenced only in comments** (e.g. "the primitives block above", "shared primitives", "(primitives)") at 16+ locations in `gtmStory.css`, but none of them is actually **defined** anywhere in the file, and `grep -rl` across the whole `force-app/main/default/lwc` tree finds no other file defining them either — `c/gtmBrandTokens` no longer exists on disk.
- `gtmStory.html` unconditionally applies these classes throughout the template (e.g. `class="boxed ps-grid"` on every section, `class="pc-full hero-nav rv d2"`, `class="pc-rail eyebrow rv"`, `<div class={proofClass}>` where `proofClass` includes `rv d3`), so on every real render — in-app and in the Content Manager preview alike — the grid collapses to unstyled block stacking with no gutter, no inter-section rhythm/padding, and no reveal-driven spacing, and any icon+label alignment that depended on the missing primitive rules (rather than the still-present component-local rules like `.cc-ic`/`.faq-verdict`) breaks. This matches every symptom in the issue.
- The commit's own verification note only ran `npx jest` (213 passed / 3 skipped) — Jest here does not render real CSS layout, so a missing-selector regression like this would never fail that suite. That is exactly why it shipped unnoticed.

This is not an ambiguous/design-fork issue — it is a straightforward missing-code regression with a clear, git-verifiable root cause and no live-data (`gtm-prod`) risk (CSS-only LWC change).
