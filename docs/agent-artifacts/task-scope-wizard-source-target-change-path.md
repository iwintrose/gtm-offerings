# TASK SCOPE — ISSUE #wizard-source-target-change-path

## 1. Requirements Breakdown

- **Target Objective:** In the "New engagement link" wizard (`gtmConfigWizard`, also mounted by `gtmConfigurator` and `gtmOverview`), a rep must be able to (a) capture **Source platform** and **Target platform** on BOTH the Quick path and the Full walkthrough, and (b) use "Change path" at ANY point without losing entered data. Product-owner decisions are final.
- **System Component Impacted:** LWC (`gtmConfigWizard` .js/.html/.css + `__tests__/gtmConfigWizard.test.js`) and Apex (one new small read-only `@AuraEnabled(cacheable=true)` method + Apex test) and Permission Sets. No Experience Cloud route change, no YAML instrument change.

### Verified current state (checked against code, not the investigation alone)

- `SOURCE_PLATFORM`/`TARGET_PLATFORM` have no input in the wizard. `_cmsDefaults` is read from `getPageLayout` content `defaults::defaultSourcePlatform` / `defaults::defaultTargetPlatform` (gtmConfigWizard.js ~370-373). Merged into `_state` only in `handleQuickGenerate` (~1162-1165) as `{...this._cmsDefaults, ...this._state, ...}`. Full never merges. The link URL builder pushes `src`/`tgt` from `_state` (~1395-1396).
- **Precedence claim needs a correction:** in `{...cmsDefaults, ...state}` the LATER spread wins, so typed `_state` values already beat defaults, UNLESS `_state.SOURCE_PLATFORM` is present-but-`undefined`/empty string (an explicitly-set empty key overrides a default only in the reverse direction; an `undefined` key in state DOES overwrite the default with undefined). Today nothing sets these keys, so the bug is latent and only becomes real once the new inputs exist (a cleared input yielding `''`/`undefined`). Requirement stands: typed non-blank value wins; blank/undefined falls back to the CMS default. Architect: build the merge so blank/undefined keys do not clobber defaults.
- `TOTAL_STEPS = 8` (~37). Step labels array at ~947: `['Company','Industry','Colour','Environment','Note','Contact','Password','Review']`. Step 4 is "Environment" (S/M/L cards + exact numbers).
- "← Change path" (`handleBackToChooser`, ~445; HTML line 367) exists only on Full step 1. `handleBackToChooser` sets only `_path='choose'` and clears `_saveError`, so entered data is preserved (already true).
- Quick Done: `handleQuickGenerate` sets `_quickStep = 2` then `_save()`. In `_save` (~1274-1277) `_existed = true` is set only when `advance && _path === 'full'`. `showEditDetails` = `_existed && isDone` (~1027), so "Edit the details" (HTML ~408) never shows on Quick. `handleEditDetails` (~1030) only sets `_step = 1` (a Full concept), so it is NOT usable on Quick as written.
- `isDone` (~1407): Full `_step > TOTAL_STEPS`, Quick `_quickStep === 2 && !!_generatedUrl`.
- **Stored value format (checked):** the CMS defaults are free-text page-content fields (`gtmPageLayouts.js` 'offering-defaults' text fields). The configurator page reads the value verbatim (`gtmConfigurator.js` 564-565, `tokenValue('SOURCE_PLATFORM')`, `sourceDisplay` ~1002, and `sourcePlatformPrefill` ~1007 passed to the booking form for option pre-selection), and the `src`/`tgt` URL params overwrite it (~687-688). So the stored value is a **human display string, not a platform key**. `GtmMigrationPairs` deliberately treats platform text as free text and resolves it via `Aliases__c` (case/punctuation-insensitive). Therefore: **store the `Display_Label__c` string** in `SOURCE_PLATFORM`/`TARGET_PLATFORM` (same format as the CMS defaults and what the page renders). Do NOT store `Platform_Key__c`; the page would render "sfmc" to a prospect.
- Platform data: `GTM_Migration_Platform__mdt` records (eloqua, hubspot, mcae, sfmc, sfmc_next) with `Platform_Key__c`, `Display_Label__c`, `Aliases__c`, `Family_Key__c`, `Active__c`. `GtmMigrationPairs.cls` (`public with sharing`) already has a private `loadPlatforms()` (SOQL at ~151, `platformOverride` @TestVisible seam) but exposes no list method. Grep found no existing Apex returning the platform list to LWC. `gtmConfigData.js` FIELDS labels for these are vestigial (unused by the wizard).
- Where the wizard runs: mounted in `gtmConfigurator.html` (~18, behind `customizeOpen`, rep/config-manager surface; `isConfigManager` gate) and `gtmOverview.html`. It calls rep-only Apex (`GtmSavedConfigurationController`), so it is an internal rep tool, not guest-facing. Guest-context access is therefore NOT needed unless the Architect finds the mount reachable by guests (see fork F4).

### Requirement detail

1. **Inputs.** Add a Source platform and a Target platform picker (`lightning-combobox` or existing pattern in the wizard), options from `GTM_Migration_Platform__mdt` `Display_Label__c` (Active__c = true), with the offering's CMS default (`_cmsDefaults`) preselected. Quick: on its single screen. Full: on step 4, retitled e.g. "Their environment" (update the labels array ~947 and step heading/HTML; NOT a new step; `TOTAL_STEPS` stays 8, dot count unchanged). Any test asserting the label text "Environment" must be updated and called out.
2. **Apex.** Add a read-only method (suggested `GtmMigrationPairs.listPlatforms()` or a tiny new wizard-facing class) returning a list of `{ key, label }` for active platforms, ordered by label, `@AuraEnabled(cacheable=true)`, `with sharing`, zero DML, reusing `loadPlatforms()`/`platformOverride`. Cacheable so LWC uses `@wire` or imperative cached call.
3. **Persistence.** Both paths persist `SOURCE_PLATFORM`/`TARGET_PLATFORM` into the same `_state` keys that go into `Config_Payload__c` JSON and the `src`/`tgt` link params. Full path merges CMS defaults into `_state` too (at load/seed time so the picker shows the default and it is saved even if the rep never touches step 4). Quick: typed non-blank value wins over default (see precedence note above).
4. **Change path everywhere.** "← Change path" must show on every Full step 1-8 (steps 2-8 currently only Back + dot rail) and on the Quick Done screen. Quick save must make "Edit the details" work: set `_existed = true` on Quick save too, and `handleEditDetails` must, on Quick, return `_quickStep = 1` (form with data intact) rather than `_step = 1`. Path change and Edit must not lose entered data (add tests).
5. **Out of scope:** changing the offering inside the wizard; the autosave orphan-draft problem (issue #99 status work); the pair-support verdict display; any edit to `GtmMigrationPairs` gate logic.

### Open forks for the Architect (do not guess)

- **F1 "Other / not listed":** the value is free text end to end and `GtmMigrationPairs` resolves free text via aliases, and fails open for unknown platforms, so the data model DOES tolerate an unlisted value. But the product owner only authorised it "if the data model supports it." Recommend: include a final "Other (type it)" option that reveals a text input and stores the typed string, since the page and gate both accept free text. Architect to confirm; the safe minimum is picker-only.
- **F2 CMS default not in the list:** `defaultSourcePlatform` is free text and may not exactly match any `Display_Label__c` (e.g. abbreviation). Options: match via existing `resolvePlatformKey` aliases server-side to preselect, or fall back to showing it as the "Other" value. Architect to choose; verify what the live default values are (read-only, `gtm-dev` is production, do NOT modify data).
- **F3 Blank selection:** can a rep clear a platform (leave blank so the page falls back to the CMS default)? Recommend yes via an empty first option, with blank = "use offering default".
- **F4 Permissions:** `GTM_Offering_User` currently grants `GTM_Offering__mdt` only via `customMetadataTypeAccesses`; `GTM_Migration_Platform__mdt` is granted to `GTM_Content_Manager`, `GTM_Content_Admin`, `GTM_Guest` but NOT to `GTM_Offering_User` or `GTM_Offering_Admin` (verified by grep). If the Apex is `with sharing` on custom metadata, custom-metadata types need the type access for a non-admin rep. Add `customMetadataTypeAccesses` for `GTM_Migration_Platform__mdt` to `GTM_Offering_User` and `GTM_Offering_Admin`, and grant the new Apex class (`classAccesses`) to `GTM_Offering_User`, `GTM_Offering_Admin` (and `GTM_Content_Manager` if that role can open the wizard). Guest set needs no change unless the mount proves guest-reachable. Note the existing `GtmMigrationPairs` runs from guest assessment context, so its existing grants stay untouched. Alternative for Architect: `without sharing` is not needed for CMDT reads; avoid it.
- **F5 Full-path default seeding timing:** `_cmsDefaults` loads asynchronously after `getPageLayout`; seeding `_state` must not overwrite a value the rep typed before the promise resolved, nor a value restored from a reopened saved link (`_knownRecordId`/query params `src`/`tgt`).
